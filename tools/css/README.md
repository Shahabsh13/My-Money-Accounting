# ابزارهای CSS (مرحله ۳ — جداسازی CSS/UI)

```bash
npm run css:inventory      # سیاهه‌ی کامل: فایل‌ها، قاعده‌ها، !important، کد مرده  → JSON
npm run css:audit          # بازبینی !important: چه چیزی را می‌توان بی‌خطر حذف کرد   → JSON
npm run css:bundles:check  # بررسی وضعیت فعلی با سند اثبات docs/css-bundle-verification.json
node tools/css/build-bundles.cjs   # اجرای واقعی ادغام + بازنویسی index.html + حذف فایل‌های اصلی
```

## چرا ادغام CSS بی‌خطر است؟

آبشار (cascade) به **ترتیب قاعده‌ها** حساس است، نه به تعداد فایل. `build-bundles.cjs` فقط
فایل‌هایی را جمع می‌کند که در ترتیب `<link>`های `index.html` **پشت‌سرهم** هستند و جای لینک‌ها را
هم عوض نمی‌کند، بنابراین ترتیب قاعده‌ها در عمل بیت‌به‌بیت حفظ می‌شود. سه شرط لازم و کافی:

1. هیچ `@import` و هیچ `@charset` در پروژه نباشد (هر دو با ادغام معنای فایل را عوض می‌کنند). اکنون برقرار است.
2. مسیرهای `url()` نسبی با جابه‌جایی فایل‌ها نشکنند؛ بسته‌ها در همان پوشه‌ی `src/styles/` ساخته می‌شوند، پس `../../assets/fonts/...` دست‌نخورده می‌ماند.
3. فایل‌هایی که کد یا آزمون به آن‌ها ارجاع می‌دهد، مستقل بمانند:
   - `043-hesabno-page-open-close-motion.css` (آزمون `performance-regression` با مسیر دقیق می‌خواندش)
   - `235-hesabno-text-root-and-display-stability.css` (لایه‌ی پچ رابط؛ برای بازبینی/بازگردانی ساده‌تر است)

## اثبات در همان اجرا

`build-bundles.cjs` پیش و پس از ادغام، فهرست «امضای قاعده‌ها» را می‌سازد
(`at-rule|selector|body` به ترتیب آبشار) و باید عنصر‌به‌عنصر برابر باشند؛ نتیجه در
`docs/css-bundle-verification.json` ثبت می‌شود (تعداد قاعده‌ها، SHA-256 هر دو فهرست، نقشه‌ی فایل‌ها و بایت‌ها).
اگر نابرابر باشد، ابزار **هیچ فایلی را نمی‌نویسد** و با کد خطا خارج می‌شود.
پس از ادغام، `--verify` وضعیت فعلی را با همان سند مقایسه می‌کند؛ اگر کسی استایل‌ها را عوض کند و سند را
به‌روزرسانی نکند، آزمون `tests/css-bundle-integrity.test.cjs` می‌شکند.

## بازبینی `!important`

`css-important-audit.cjs` بر پایه‌ی یک قاعده‌ی محافظه‌کارانه کار می‌کند: پرچم `!important` تنها وقتی
«حذف‌شدنی» اعلام می‌شود که **هیچ رقیب با مقدار متفاوت و وزن/ترتیب بالاتر** در کل CSS وجود نداشته باشد،
ویژگی در `@keyframes` نیامده باشد، و برنامه آن ویژگی را به‌صورت استایل درون‌خطی ننویسد
(استایل درون‌خطی برنده‌ی اعلان‌های normal است). با `--apply` فقط همین موارد اثبات‌پذیر حذف می‌شوند.

خروجی فعلی (مرحله ۳): از ۱۶۰۹ اعلان مهم در ۶۵۳ قاعده، فقط **۲۹** مورد اثبات‌پذیر است
(۱٫۸٪)؛ بقیه به دلیل استایل درون‌خطی (۱۲۲۸)، سلکتور نامطمئن/تودرتو (۱۸۴)، انیمیشن (۷۱) و
رقیب قوی‌تر با مقدار متفاوت (۹۷) دست‌نخورده می‌مانند. جزئیات در `docs/css-important-audit.json`.
