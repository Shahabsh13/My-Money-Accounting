# میزسنج (Benchmark) پروژه‌ی My Money

این پوشه ابزار اندازه‌گیری «قبل و بعد» را نگه می‌دارد؛ سه اسکریپت مستقل Node هستند و هیچ
وابستگی به برنامه‌ی اندروید یا سرور ندارند.

```bash
npm ci                 # jsdom لازم است
npm run bench          # خروجی JSON روی stdout: node tools/bench/bench.cjs > docs/bench-baseline.json
npm run bench:churn    # نرخ تغییرات DOM و فریم‌ها پس از راه‌اندازی
npm run bench:idle     # پروفایل «آشوب بیکاری»: چه کدی بی‌دلیل فریم/نوشتن ذخیره‌سازی می‌سازد
```

هر سه اسکریپت ریشه‌ی پروژه را از محل خودشان (`__dirname/../..`) می‌سازند و jsdom را از
`node_modules` پروژه می‌خوانند، پس روی هر ماشین و هر مسیری اجرا می‌شوند. مسیر ریشه را می‌توان
به‌صورت آرگومان هم داد: `node tools/bench/bench.cjs /path/to/repo`.

## خروجی `bench.cjs`

| بخش | معنی | پایداری |
| --- | --- | --- |
| `static` | تعداد و بایت اسکریپت‌ها/استایل‌ها/تگ‌های index.html | دقیق و تکرارپذیر |
| `parse.ms` | زمان کامپایل همه‌ی اسکریپت‌ها با `vm.Script` (بدون اجرا) | نوسان دارد |
| `boot.*` | راه‌اندازی کامل برنامه در jsdom (میانه‌ی ۳ اجرا) | نوسان دارد |
| `boot.rafPerSecondAfterBoot` | فریم‌های درخواستی پس از راه‌اندازی (حلقه‌ی داخلی jsdom هم شمرده می‌شود) | نویزی؛ فقط برای مقایسه‌ی نسبی |
| `scale` | حجم JSON و زمان ساخت/خواندن برای ۱k/۱۰k/۵۰k/۱۰۰k سند | دقیق |

## خط پایه‌ی ثبت‌شده

| مرحله | `parse.ms` | میانه‌ی راه‌اندازی | گره‌های DOM | استایل تزریق‌شده | نوشتن کل آرایه در راه‌اندازی |
| --- | --- | --- | --- | --- | --- |
| خط پایه‌ی اول (ابزار بیرون از مخزن) | ۱۱۹٫۵ | ۱۲۶۲ ms | ۷۹۲ | ۲۸ | ۸ |
| مرحله ۲ (همین ابزار درون مخزن) | ۹۴٫۶ | ۱۰۶۴ ms | ۷۹۲ | ۲۸ | — |

اعداد زمانی روی یک ماشین مشترک اندازه‌گیری شده‌اند و نوسان چند ده درصدی دارند (مثلاً اجرای
مرحله ۲ میانه‌ی ۱۰۶۴–۱۲۶۲ ms داد). برای قضاوت درباره‌ی بهبود واقعی، فقط اعداد پایدار
(`static`، `scale`، تعداد گره‌ها، تعداد استایل‌ها) قابل استناد هستند و برای زمان‌ها باید
چند بار پشت سر هم اجرا و میانه گرفته شود.

حجم داده در مرز ۵ مگابایت (سقف `localStorage`) با ~۳۱۰ بایت به‌ازای هر سند:
۱k ≈ ۳۰۳ KB، ۱۰k ≈ ۳٫۰ MB، ۵۰k ≈ ۱۵ MB، ۱۰۰k ≈ ۳۰ MB — یعنی از حدود ۱۷ هزار سند به بعد
داده در حافظه‌ی اصلی ذخیره نمی‌شود. این عدد پایه‌ی تصمیم مرحله ۶ (لایه‌ی ذخیره‌سازی) است.
