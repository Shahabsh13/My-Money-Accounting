# لایهٔ ظاهر — تغییر قیافه بدون دست‌زدن به رفتار

## این چیست، به زبان ساده

تا امروز رنگ و فونت و اندازهٔ بعضی بخش‌ها را جاوااسکریپت «روی خودِ عنصر» می‌نوشت.
یعنی اگر می‌خواستی رنگ تاریخ داشبورد را عوض کنی، باید می‌رفتی داخل یکی از فایل‌های
کدِ برنامه و عدد رنگی را پیدا می‌کردی؛ و همان تغییر، چون در مسیر اجرای برنامه بود،
خطر داشت رفتار هم عوض شود.

از این به بعد یک «لایهٔ ظاهر» داریم: همهٔ مقدارهای بصری در یک جا نوشته شده‌اند و
جاوااسکریپت فقط می‌گوید «این عنصر، تاریخ داشبورد است» یا «این، سرتیتر روز است».
یعنی **تغییر ظاهر = تغییر یک عدد در یک فایل CSS**، بدون دست‌زدن به هیچ فایل JS.

## کجا زندگی می‌کند

انتهای فایل `app/src/main/assets/src/styles/235-hesabno-text-root-and-display-stability.css`،
بخش «لایهٔ ظاهر (Appearance layer)». این فایل یکی از دو استایل مستقلی است که در
`index.html` جدا لینک می‌شود، پس همین فایلِ روی دیسک، همان چیزی است که برنامه
اجرا می‌کند (واسط یا بستهٔ میانی در کار نیست).

## چطور ظاهر را عوض کنم

فقط مقدار متغیرها را در بلوک `:root` عوض کنید:

```css
:root {
  --hesabno-ui-font: "Vazirmatn", system-ui, sans-serif; /* فونت کل داشبورد */
  --hesabno-date-size: 11px;        /* اندازهٔ تاریخ بالای داشبورد */
  --hesabno-date-weight: 900;
  --hesabno-date-tone-dark: #f2d18a;   /* رنگ تاریخ در تم تاریک */
  --hesabno-date-tone-light: #244b59;  /* رنگ تاریخ در تم روشن */
  --hesabno-daydate-tone-dark: #b9cbd4;
  --hesabno-daydate-tone-light: #526875;
  --hesabno-dayheader-bg-dark: rgba(255, 255, 255, .055);
  --hesabno-dayheader-bg-light: #cde3de;
  --hesabno-dayheader-radius: 0;
}
```

مثال: برای دکمهٔ بستن تقویم هم `--hesabno-calendar-close-*` هست (اندازه، فاصله، رنگ).

مثال: برای اینکه تاریخ داشبورد در تم تاریک قرمز شود، فقط
`--hesabno-date-tone-dark: #ff4d4d;` را بنویسید. هیچ فایل دیگری لازم نیست.

دقیقاً همین دو رفتار را نگه داشته؛ یکسان‌سازی‌شان یک تصمیم طراحی جداگانه است، نه بخشی
از این کار.

## چطور مطمئن شویم چیزی نشکسته

- `npm test` → ۲۲۲ آزمون، همه سبز.
- سنجش مستقیم روی برنامهٔ در حال اجرا: تعداد تگ‌های `<style>` تزریق‌شده در `<head>` در زمان بوت از **۲۷ به ۱** (فقط تگ هستهٔ `067-inline.js`) رسیده و پس از استقرار صفحه، در ۲ ثانیه **صفر** نوشتن `style` روی این بخش‌ها ثبت می‌شود.
- آزمون `a body mutation does not re-style or re-text the dashboard date` و `calendar-appearance.test.cjs` غیاب تگ‌های `<style>` تزریق‌شده و غیاب `style` درون‌خطی را بررسی می‌کنند.

## چه چیزی هنوز بیرون مانده

- `067-inline.js` (هستهٔ ۲ مگابایتی) هنوز مارک‌آپ و منطق را با هم دارد؛ جدا‌کردن مارک‌آپ
  از آن یک بازنویسی بزرگ است، نه یک تغییر ظاهری.
- چند فایل دیگر هنوز برای کارهای غیرظاهری (موقعیت، اندازه‌گیری، انیمیشن) `style`
  می‌نویسند؛ این‌ها چیدمان‌اند نه ظاهر.
- فایل‌های `117` و `118` (تقویم قدیمی) در خط دوم خود `return;` دارند؛ یعنی از کار
  افتاده‌اند و استایلشان هرگز اجرا نمی‌شود. تقویمی که می‌بینید از هستهٔ `067` می‌آید و
  رنگ‌هایش با کلاس‌های Tailwind در CSS تعریف شده‌اند (نه با استایل درون‌خطی).

## قاعدهٔ کار برای تغییرهای بعدی

1. مقدار بصری جدید؟ یک متغیر `--hesabno-*` در همین بلوک اضافه کنید.
2. عنصر جدید باید ظاهر بگیرد؟ جاوااسکریپت فقط یک کلاس معنایی بگذارد؛ خودِ ظاهر این‌جا.
3. هیچ رنگ/اندازه/فونتی را در جاوااسکریپت ننویسید. آزمون
   `no application script references a CSS file path` و بازبینی سادهٔ
   `grep -n "font-family" src/scripts` جلوی بازگشت این عادت را می‌گیرد.
