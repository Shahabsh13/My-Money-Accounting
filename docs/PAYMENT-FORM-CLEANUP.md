# پاک‌سازی فرم ثبت سند (پرداخت / دریافت / انتقال)

این تغییر با اسکرین‌شات کاربر از فرم «ثبت پرداخت» شروع شد و طبق خواستهٔ «اینو هر جایی ک دیدی اعمال کن» به همهٔ
فرم‌هایی که همین الگو را دارند تعمیم داده شد.

## ۱) لبه‌های دو کادر مسیر سند موازی شد

در فرم، دو کادر «پرداخت به / دریافت از» و «از حساب / به حساب» در دو ردیف جداگانه بودند و چون هر ردیف با
`flex` و برچسبی با عرض طبیعی (`flex: 0 0 auto`) چیده می‌شد، برچسب کوتاه‌تر باعث می‌شد کادر آن ردیف از سمت راست
جابه‌جا شروع شود و لبه‌های دو کادر با هم موازی نباشد.

راه‌حل در لایهٔ پایانی `235-hesabno-text-root-and-display-stability.css` (بعد از ۰۲۰ و ۰۴۰) اضافه شد:

```css
main > form.px-4.pt-4.space-y-4 section:has(#field-party) > div:not(:first-child) > label {
  flex: 0 0 auto !important;
  min-width: 4.25rem !important;
  margin: 0 !important;
  white-space: nowrap !important;
}
main > form.px-4.pt-4.space-y-4 section:has(#field-party) > div:not(:first-child):has(> label + button + p) {
  grid-template-columns: minmax(4.25rem, max-content) minmax(0, 1fr) !important;
}
```

- عرض کمینهٔ `4.25rem` (۶۸px) از بلندترین برچسب این فرم‌ها («پرداخت به:» با ۱۲px) بزرگ‌تر است، پس هر دو برچسب
  دقیقاً یک عرض می‌گیرند و کادرها هم‌شروع و هم‌پایان می‌شوند.
- قاعدهٔ دوم همان ستون را در حالت خطای درون‌کادری (که ردیف به `grid` تبدیل می‌شود) حفظ می‌کند تا پیام خطا زیر
  همان کادر بماند و چیدمان نلرزد.
- این تغییر شهودی است، نه فقط برای فرم پرداخت: فرم‌های «دریافت»، «انتقال» و حالت «چک صیادی» هم از همان
  `section:has(#field-party)` استفاده می‌کنند و خودکار اصلاح می‌شوند.

## ۲) متن‌های راهنمای تکراری حذف شدند

| جای قبلی | وضعیت |
| --- | --- |
| زیر «این عملیات کارمزد دارد»: «ثبت خودکار در سرفصل «کارمزد بانکی»» | حذف |
| زیر عنوان پیوست: «عکس رسید بانکی، فاکتور یا پیوست سند» / «عکس رو یا پشت برگه چک صیادی جهت بایگانی دیجیتال» | حذف |
| دکمهٔ پیوست: «انتخاب تصویر فیش» / «انتخاب تصویر چک» | «انتخاب تصویر» (با `whitespace-nowrap` تا دوخطی نشود) |
| زیر دکمهٔ ثبت: «تکمیل مبلغ و حساب‌های مبدأ و مقصد برای ثبت سند الزامی است.» / «مجموع حساب‌های مبدأ و مقصد باید تراز بوده و ردیف‌ها دارای حساب و مبلغ باشند.» | حذف |

هر دو نسخهٔ فرم پاک شدند: JSX فشردهٔ فرم اصلی و بازنویسی `wrapPaymentJsx` (پنل «پرداخت و تسویه قسط» که برای
ثبت تراکنش وام/قسط استفاده می‌شود). پنل پرداخت جایگزین چک برگشتی
(`144-hesabno-check-return-confirm.js`) هم همان متن‌ها را داشت و پاک شد.

عمداً دست‌نخورده ماند:

- عنوان‌های خود بخش‌ها («این عملیات کارمزد دارد»، «تصویر فیش / سند پیوست»، «تصویر چک»).
- مودال «افزودن تصویر پیوست» با دو گزینهٔ «ثبت عکس با دوربین» و «انتخاب از گالری گوشی»؛ این یک انتخاب واقعی
  است، نه متن راهنما.
- متن دکمه‌های انتخاب فایل در بازیابی پشتیبان («انتخاب فایل پشتیبان پارمیس» و…).

## ۳) آزمون‌ها

`tests/payment-form-cleanup.test.cjs`:

1. نسخهٔ بستهٔ اسکریپت‌ها هیچ‌کدام از متن‌های حذف‌شده را ندارد و عنوان‌ها/دکمهٔ جدید را دارد.
2. پنل پرداخت جایگزین چک برگشتی همان پاک‌سازی را دارد.
3. قاعده‌های هم‌عرض‌کردن کادرها در لایهٔ ۲۳۵ ثبت شده‌اند.
4. برای هر سه فرم «پرداخت»، «دریافت» و «انتقال» (در jsdom): متن‌های اضافه نیست، هر دو کادر عرض کمینهٔ برابر
   `4.25rem` دارند و دکمهٔ پیوست فقط «انتخاب تصویر» است.

`docs/css-bundle-verification.json` با کلید جدید `paymentRouteAlignment` (۲ قاعده) و `currentState` به‌روزرسانی شد
(۱۰ فایل، ۳۳۹۵ قاعده، ۸۴۶۰۰۹ بایت) و فرمول `tests/css-bundle-integrity.test.cjs` هم همان کلید را جمع می‌زند.
