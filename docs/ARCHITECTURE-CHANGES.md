## ۱) معماری پیش از تغییر

```
index.html
 ├─ 135 <script defer>  ← زنجیره‌ی وصله‌ها (000 … 235)
 │    • 067-inline.js: هسته‌ی مینیفای‌شده (React + منطق حسابداری) — غیرقابل بازآرایی
 │    • بقیه: وصله‌هایی که رفتار را «از بیرون» تغییر می‌دهند (CSS تزریقی، observer، گوش‌دهنده)

 └─ بدون آزمون، بدون لایه‌ی دامنه، بدون قرارداد مکتوب
```

مشکلات ساختاری که در بازرسی مرحله ۱ با شواهد ثبت شد:

1. **وصله روی وصله** — چند اسکریپت هم‌زمان یک چیز را می‌پیچیدند (۴ مورد روی `setItem`).
2. **ناظرهای DOM پراکنده** — ۱۰۷ ناظر ایستا در ده‌ها فایل، با هم‌پوشانی و هزینه‌ی بوت.
3. **منطق مالی فقط داخل باندل ۰۶۷** — غیرقابل آزمون، غیرقابل بازآرایی، غیرقابل مستندسازی.
4. **مسیرهای داده‌ی موازی** — سه مسیر پشتیبان/بازیابی با فهرست‌ها و اعتبارسنجی‌های متفاوت.
5. **هیچ شبکه‌ی امنیتی برای تغییر** — هیچ آزمون یا سنجه‌ای وجود نداشت که «عوض نشدن» را ثابت کند.

```
index.html
```

نکته‌ی کلیدی معماری: **لایه‌ی خالص عمداً از بوت جدا است.** `src/domain/` و `src/application/`
در `index.html` بارگذاری نمی‌شوند (آزمون قفلش می‌کند)؛ بنابراین صفر بایت هزینه‌ی بوت دارند و
فقط آزمون‌ها/ابزارها آن‌ها را می‌خوانند. این تصمیم اجازه داد بدون دست‌زدن به هسته‌ی قفل‌شده،
منطق مالی را خوانا، آزمون‌پذیر و ۱۳ برابر سریع‌تر کنیم.

## ۵) الگوهای معماری‌ای که اضافه شدند

1. **نقطه‌ی گلوگاه واحد (Single choke point)**
   به‌جای N وصله‌ی موازی: یک رجیستری ناظر (۲۳۶)، یک نگهبان مهاجرت (۰۰۵b)، یک نگهبان نوشتن،
   یک رجیستری کلید، یک قرارداد پشتیبان. مشترک‌شدن (subscribe) جای «پیچیدن توابع» را گرفت.

2. **آزمون تفاضلی در برابر هسته‌ی قفل‌شده**
   منطق مالی داخل باندل مینیفای‌شده قفل است. به‌جای بازنویسی، نسخه‌ی خالص ساخته شد و
   **مو‌به‌مو** با توابع واقعی `Nr`/`Cs`/`gk` مقایسه شد. اگر روزی واگرا شود، آزمون می‌شکند.

3. **صفر هزینه‌ی بوت برای کد تازه**
   دامنه/کاربرد در `index.html` نیست؛ آزمون `not loaded by index.html` قفلش می‌کند.

4. **سازگاری عقب‌رو به‌عنوان قرارداد**
   فایل پشتیبان ۲۳ کلیدیِ نسخه‌ی قبل پذیرفته و بازیابی می‌شود؛ پشتیبان قدیمی کلید تازه را
   نه می‌سازد نه پاک می‌کند.

5. **اندازه‌گیری پیش از ادعا**
   هر مرحله سند + JSON سنجه دارد: `bench-baseline`, `dom-equivalence-*`,
   `report-bench`, `sync-bench`, `storage-keys`, `css-important-audit`.

6. **بازگشت‌پذیری یک‌خطی**
   هر تغییر بزرگ یک سوئیچ/فهرست دارد: `skipUnchanged` (یک خط)، حذف کلید از `backupKeys`،
   حذف ماژول دامنه، `SKIP_PATTERNS` در کدساز ناظر.

   از پیش موجود که در کامیت تلفیقی جذب شد). چون تاریخچه بازسازی شده، **نسبت‌دادن به مرحله‌ی

3. **کامیت تلفیقی `678a87d` شامل کارهای خارج از مراحل ۴–۹ هم هست** (کیبورد ۲۱۴/۲۲۵ و چند فایل

   (۴۰ نقطه‌ی ساخت در ۳۱ فایل). بزرگ‌ترین‌ها: ۲۲۵ (۱۳٬۶۰۸ B)، ۱۴۰ (۴٬۸۳۷)، ۲۱۴ (۴٬۱۹۰)،
   ۱۴۵ (۳٬۹۵۲)، ۲۱۷ (۳٬۳۳۴)، ۲۰۲ (۲٬۱۶۶)، ۱۴۲ (۲٬۱۳۳)، ۱۳۸ (۱٬۷۵۱)، ۰۶۷ (۱٬۷۱۵).
   از این مقدار **۳۸٪ فقط در ۲۱۴ و ۲۲۵** است که طبق محدودیت شما خارج از محدوده‌اند.
3. **۳۵۶ دستکاری مستقیم `style.*` در ۵۳ فایل** — ظاهر به‌صورت imperative از JS عوض می‌شود.
4. **۱٬۶۰۹ اعلان `!important`** در باندل‌ها (۲۹ مورد کاندید حذف شناسایی شد، هیچ‌کدام بدون تصمیم حذف نشد).

### ۹-۳) حکم

* از نظر **حجم**: ۹۳.۴٪ CSS در فایل است، ۶.۶٪ در JS.
* از نظر **معماری**: جدایی کامل نیست. CSS جدا شده، اما «ظاهر» = مارک‌آپ + کلاس + تزریق + دستکاری
  مستقیم، و هر چهار مورد هنوز به کد بیس/وصله‌ها چسبیده‌اند.
* **استخراج مارک‌آپ از ۰۶۷ توصیه نمی‌شود** (ریسک بالا، سود کم، هسته‌ی قفل‌شده).

### ۹-۴) گام پیشنهادی مرحله ۱۰ (نیازمند تأیید)

انتقال ۲۲ نقطه‌ی تزریق استایل (به‌جز ۲۱۴/۲۲۵) از JS به باندل‌های موجود: حدود **۲۸.۵ KB (۶۱٪)**
از CSS تزریقی از کد وصله بیرون می‌رود، با قفل چکیده‌ی DOM و آزمون CSS. بدون تغییر ظاهر.
